# PersonalAI 4.2.0 — гибридный персональный ИИ для Windows 11

## Новое в 3.8.0 — менеджер локальных GGUF-моделей

- Кнопка **«Мои модели»** открывает отдельный каталог моделей. Пользователь сам выбирает папку; программа смотрит только файлы `.gguf` непосредственно в этой папке (не рекурсивно), максимум 500 записей. Сканирование не отправляет файлы в интернет.
- Для каждого файла читаются сигнатура `GGUF`, версия заголовка (1–3) и размер. Файл с неверным заголовком отклоняется. **Проверка заголовка не подтверждает подлинность, безопасность или работоспособность модели.**
- По отдельной команде можно вычислить SHA-256 выбранной модели (до 14 ГиБ) и сверить с хэшем доверенного источника. Автоматического доверия по хэшу без внешнего эталона нет.
- Кнопка «Выбрать для сервера» после подтверждения сохраняет путь к модели в настройках. **Модель не запускается** и никаких системных команд это окно не исполняет.
- Добавлены осторожные подсказки по объёму памяти для целевого ПК с RX 580 8 ГБ. Эти подсказки не являются проверкой GPU-ускорения: Vulkan и реальная производительность по-прежнему не тестировались.
- Добавлены 11 модульных тестов; текущий результат **107/107**. Smoke-тест главного окна и окна моделей выполнен в Linux/Xvfb.

**Полный самостоятельный ZIP с исходным кодом, тестами и средствами сборки Windows (НЕ готовый EXE).** Продолжает версию 2.0.0 без удаления существующих данных. Целевой ПК: Ryzen 5 3600, RX 580 8 ГБ, ОЗУ 24 ГБ, свободное место 20–50 ГБ. Никаких тестов на ПК пользователя пока не требуется.

## Ранее: 3.5.0 — конструктор контролируемых сценариев

- В разделе **«Сценарии» → «Конструктор»** можно подготовить собственную последовательность из 1–8 шагов. Сейчас доступны **только** `audit` (локальный аудит проекта) и `snapshot` (локальный снимок контрольных сумм). Это не оболочка для выполнения команд.
- Формат плана — строгий JSON без Markdown: `{"title":"Проверка проекта","steps":["audit","snapshot"]}`. Разрешены только поля `title` и `steps`; неизвестные поля, повторяющиеся JSON-ключи, пользовательские пути и произвольные операции отклоняются. Максимальный размер документа — 4096 символов.
- Перед сохранением приложение показывает папку проекта, название и каждый этап. Требуется явное подтверждение создания. **Создание не запускает сценарий**: каждый шаг по-прежнему требует отдельного подтверждения.
- План можно подготовить текстом самостоятельно либо скопировать из ответа ИИ, но ответ ИИ не выполняется и не создаёт сценарий автоматически.
- В выпуске 3.5.0 были добавлены 7 тестов; в текущем релизе всего **107/107**. Сохранены тесты предыдущих выпусков.

## Сохранено из 3.3.0 — разрешённые приложения и восстановление сценариев

- **Окно «Программы Windows»**: открывает только три известные встроенные программы: Блокнот, Калькулятор и Проводник. Пользователь вручную выбирает программу и отдельно подтверждает запуск. Используется абсолютный путь из каталога Windows/System32, аргументы отсутствуют, `shell=False`. Ответы ИИ не могут инициировать эту операцию, произвольный EXE/PowerShell не поддерживается. Успех/отказ записывается в локальный журнал. На Linux это окно есть для проверок интерфейса, но запуск Windows-приложений блокируется.
- **Восстановление сценариев после прерывания**: сценарий, оставшийся со статусом `running`, можно *вручную* пометить ошибочным, только если этап длится не менее 24 часов. Приложение не запускает операцию повторно при восстановлении. Перед возможным повтором нужно проверить состояние файлов/снимков: предыдущая операция могла выполниться частично. Повторный запуск также требует отдельного подтверждения.
- **Тесты**: в текущем релизе 107/107 автоматических тестов. Добавлены проверки allowlist, запрета выполнения без разрешения, неизменяемых аргументов запуска, недопустимых каталогов, возрастного ограничения для восстановления и защиты от повторного восстановления.
- **Согласование версии**: сценарий сборки и Inno Setup ожидают артефакты с номером 3.8.0. Исходный код не комплектуется моделью, Vulkan-бэкендом или готовым EXE.

## Сохранено из 3.0.0 — контролируемые многошаговые сценарии

- Кнопка **«Сценарии»** в главном окне открывает менеджер длительных заданий с сохранением этапов и результатов в локальную SQLite-базу.
- Три фиксированных сценария: `audit_snapshot` (аудит исходников, затем снимок контрольных сумм), `audit_only` и `snapshot_only`.
- **Каждый этап запускается вручную отдельной кнопкой и отдельным подтверждением.** Никакие следующие шаги автоматически не выполняются. Предусмотрены просмотр, отмена невыполненных шагов, повтор неудачного шага после нового подтверждения.
- Сценарии не принимают произвольные команды, не запускают PowerShell/терминал/исходники и не отправляют материалы в сеть. Аудит и снимок используют уже существующие ограниченные локальные механизмы программы. Снимки сохраняют пути и хэши; текст аудита содержит только находки и пути, **не полный исходный код**.
- При перезапуске незавершённые задания сохраняются. Обработка выполненного шага повторно запрещена. Сценарий не является полнофункциональным универсальным агентом: это безопасная основа оркестрации.
- Для прежних данных создаются новые таблицы `workflows` и `workflow_steps`. Старые таблицы не удаляются.
- Сохранены тесты предыдущих релизов, включая повторное выполнение, сбой этапа, запрет неподдерживаемой операции и требование разрешения. Всего в 3.8.0 **107** тестов.

## Сохранено из 2.9.0 — локальные снимки изменений проекта

- **Снимки проекта** — новый раздел главного окна. По явной команде пользователя программа сканирует выбранную рабочую папку и сохраняет в SQLite только относительные пути, размеры файлов и SHA-256. Содержимое файлов не копируется и не передаётся в ИИ.
- Можно сравнивать два сохранённых снимка, экспортировать текстовый отчёт или сравнивать сохранённый снимок с текущими файлами. Сравнение показывает добавленные, изменённые и отсутствующие файлы. Снимок можно удалить, не изменяя проект. Отдельные операции записываются в журнал.
- Сканирование ограничено 1500 файлами, 8 МиБ на файл и 96 МиБ суммарно; не проходит по символьным ссылкам и папкам окружений/сборки, пропускает распространённые файлы секретов. Ограничения и пропуски учитываются в отчёте: сравнение может быть неполным. **Это учёт изменений, не система резервного копирования и не гарантия отсутствия изменений в пропущенных файлах.**
- Дополнены модульные тесты: обнаружение новых, изменённых и удалённых файлов; защита от символьных ссылок; исключения секретных файлов; соблюдение лимитов; отсутствие сохранённого содержимого.

## Ранее реализовано — автономный локальный аудит исходников

- **Аудит проекта**: новая кнопка в главном окне сканирует выбранную рабочую папку без сети и без исполнения исходников, проверяет синтаксис файлов Python и JSON, собирает пометки TODO/FIXME и сообщает о *возможных* секретах в строках (значения не выводятся).
- Обход ограничен первыми 600 файлами и первыми 200 находками, чтение до 128 КиБ на файл, исключаются явные файлы секретов и неподдерживаемые форматы. Применяются ограничения существующей рабочей области и запрет символьных ссылок.
- Отчёт отображается в отдельном окне. Исходники и результаты не отправляются в облако и не сохраняются автоматически.
- **Исправлена сборка**: Github Actions теперь ожидает настоящее имя установщика текущего релиза, `PersonalAI-Setup-3.8.0.exe`, вместо ошибочного `2.0.0`.
- Проверки синтаксиса Python/JSON не гарантируют исправность проекта, а поиск секретов эвристический; отчёт не заменяет специализированный аудит безопасности.

## Сохранено из 2.6.0

- **Очередь проверки изменений.** Когда ИИ предлагает JSON-план, предложенные записи файлов **не исполняются**, а сохраняются локально в SQLite как отдельные этапы. Кнопка «Очередь проверки» открывает очередь после перезапуска приложения. Каждый этап можно просмотреть в виде diff, отдельно подтвердить либо отклонить. ИИ не запускает shell-команды, программы и сетевые действия. Сохраняется прежнее ограничение: не более 4 файлов, максимум 512 КиБ каждый, запись только в выбранной пользователем рабочей области и только в существующие папки. Перечень имён файлов может передаваться облачной модели лишь после подтверждения.
- **Защита очереди.** Для записи нужен отдельный одобрительный ответ в GUI. Перед заменой файла сверяется SHA-256 с моментом предпросмотра, при изменении файла операция отклоняется. Записи выполняются с резервной копией прежнего файла. Повторное применение обработанного этапа блокируется.
- **Поиск по сообщениям.** Кнопка «Поиск» находит буквальную подстроку без SQL-подстановок, включая русские буквы, по последним 10 000 сохранённым сообщениям (не более 100 результатов). Можно перейти к нужному диалогу. Поиск выполняется локально и не отправляет переписку провайдерам ИИ.
- **Приватность/удаление старого формата.** В «Хранилище» появилась отдельная операция удаления legacy-истории из таблицы `history` с двойным подтверждением. Современные диалоги и импортированные сообщения сохраняются. SQLite не обеспечивает гарантированного физического стирания с диска; для полной очистки носителя нужны внешние средства.
- **Компоновка.** Длинные панели действий разбиты на более короткие ряды для окон небольшой ширины.

## Сохранено из 2.3.0 — контекст проекта

- **Окно «Контекст проекта»**: фильтрация файлов по имени и поиск буквального текста внутри файлов локально, без облачного поиска. Поддерживаются распространённые текстовые форматы исходного кода и документации. Папки `.git`, `node_modules`, `.venv`, `__pycache__` обходятся стороной.
- **Точный выбор перед передачей**: выдели от 1 до 8 текстовых файлов и напиши конкретный вопрос. Перед отправкой показываются имена, размеры и короткие контрольные суммы SHA-256. Ограничение 32 КиБ на файл, 96 КиБ суммарно. Выход за пределы рабочей папки и символьные ссылки блокируются. Файлы не изменяются.
- **Приватность**: нет скрытой индексации или фоновой отправки проекта. Контент в запрос добавляется только после отдельного подтверждения. В облачном режиме и при разрешённом гибридном fallback выбранные данные могут попасть внешнему ИИ-провайдеру. Сам текст переданных файлов не сохраняется в историю чата; ответ ИИ сохраняется. ИИ не исполняет инструкции из файлов.
- **Ограничения**: это анализ выбранных файлов, не полноценный RAG и не автоматическое редактирование проекта. Поиск в содержимом ограничен первыми 350 подходящими файлами (до 32 КиБ каждый); количество результатов — максимум 100. Полноценного графического теста Windows не проводилось.

## Сохранённые функции предыдущих версий

Гибридный чат (llama.cpp/OpenAI-совместимый API), независимые диалоги, потоковые ответы с отменой, приватный по умолчанию fallback, заметки, ручные задачи, текстовый редактор в ограниченной рабочей папке, резервные копии, журналы операций, диагностика, запуск выбранного пользователем `llama-server.exe`, загрузчик GGUF по HTTPS с проверкой SHA-256, Vosk-диктовка и озвучка Windows SAPI. API-ключ не записывается в настройки, а данные SQLite и резервные копии пока **не зашифрованы**.

## Сборка Windows

1. Создай приватный репозиторий и загрузи **всё содержимое этого ZIP**, включая скрытую директорию `.github`.
2. На GitHub открой **Actions → Build Windows EXE and Installer → Run workflow**.
3. После успешной сборки в артефактах ожидаются `PersonalAI-v3.8.0-Windows-portable` и `PersonalAI-v3.8.0-Windows-Setup`.
4. Внутри ожидаются `PersonalAI.exe` и `PersonalAI-Setup-3.8.0.exe`. Это ожидаемые имена результатов workflow, не собранные и не проверенные в этой среде установщики.

Для разработки: Python 3.10+ c Tkinter, `python -m pip install -r requirements-build.txt`, `python -m unittest discover -s tests -v`, `python -m assistant_app.main`.

## Ограничения

Локальный `llama-server.exe`, GGUF-модель и Vosk-модель **не включены** в архив: программа остаётся исходным проектом, не автономным офлайн-дистрибутивом. Совместимость RX 580/Vulkan и реальная сборка EXE на Windows не проверены. Графический smoke-тест в Linux/Xvfb не заменяет полноценное тестирование Windows GUI. Очередь не выполняет автономных системных задач — это специально ограниченный механизм подтверждения *текстовых* изменений.

Снимки содержат пути и хэши — эти сведения могут раскрывать структуру проекта. Хранилище SQLite не зашифровано. Снимки не создаются автоматически.

Данные приложения находятся в `%LOCALAPPDATA%\PersonalAI`. Перед обновлением рекомендовано сделать копию этого каталога. В этой версии схема базы расширяется автоматически без удаления прежних таблиц.


## Новое в 4.0.0 — мастер локального ИИ

- **Мастер локального ИИ** в главном окне предлагает три явных профиля: CPU (0 слоёв GPU, контекст 2048), осторожный Vulkan (8 слоёв, контекст 2048) и расширенный Vulkan (20 слоёв, контекст 4096). Это лишь начальные значения параметров, НЕ подтверждение совместимости RX 580.
- До применения показывает значения и локальный отчёт о наличии `llama-server.exe`, выбранной GGUF-модели и локальном URL. Отчёт **не обращается в интернет и не запускает программы**.
- Сохранение параметров требует подтверждения пользователя; сервер запускается отдельно через существующее окно «Сервер ИИ».
- В отчёте отмечается отсутствие программы, модели и ненадлежащий локальный адрес. Мастер не скачивает модели, не верифицирует бинарники и не устанавливает драйверы.
- Для RX 580 рекомендуется начинать с профиля CPU. Видеоускорение Vulkan требует отдельной проверки на Windows.
- Добавлены модульные тесты для профилей, портов, URL и неисполняющей диагностики.
- Версия сборки Windows и имя Inno Setup обновлены до **4.0.0**. Полный ZIP — исходники и конфигурация сборки, **не готовый EXE**.


## Новое в 4.2.0 — проверяемое резервное копирование

- В главном окне появилась кнопка **«Архив данных»**. По явному согласию программа создаёт ZIP из `settings.json` и согласованного снимка `memory.db`, полученного через SQLite backup API.
- Архив содержит манифест с SHA-256 и размерами; после записи он проверяется. Есть отдельная кнопка **«Проверить ZIP»** без извлечения файлов.
- Архив не включает модели, код проектов, рабочие файлы и API-ключи. Неизвестные поля настроек игнорируются.
- Архив **не зашифрован**. Он может содержать приватные переписки, заметки и журнал операций; хранить только в доверенном месте.
- Автоматическое восстановление отсутствует, чтобы исключить опасную перезапись живой базы. Для восстановления нужна отдельная проверяемая процедура.
- Версия сборки обновлена до 4.2.0; полный проект исходников, не готовый EXE.
